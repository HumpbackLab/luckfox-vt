# MIS5001 720p90 / 1080p60 实现记录

日期：2026-04-22

## 1. 当前结论

当前正式保留两条高帧率 / 高分辨率路径：

- `1280x720@90`
- `1920x1080@60`

此前验证过的 `1104x624` sensor mode 和配套 `ipc_lite` ini 已移除。它仍可作为历史调试记录参考，但不再作为当前镜像里的可运行配置暴露。

## 2. Sensor 时序

`mis5001` 当前统一使用：

```text
MIPI data rate: 1080Mbps/lane
lanes: 2
RAW: 10bit
HTS: 0x0BB8
```

模式表：

```text
2592x1944@30: VTS=0x0960
1920x1080@60: VTS=0x04B0
1280x720@90:  VTS=0x0320
832x464@120:  VTS=0x0258
```

`1920x1080@60` 和 `1280x720@90` 都是基于全幅中心裁剪 ROI，不是 ISP 后级缩放出来的假分辨率。

## 3. IQ 更新

`1080p60` 需要在 MIS5001 IQ 中补 `1920x1080`，否则 RKAIQ 会缺少对应 resolution / LSC 表。

更新文件：

```text
media/isp/release_camera_engine_rkaiq_rv1106_arm-rockchip830-linux-uclibcgnueabihf/isp_iqfiles/mis5001_CMK-OT2115-PC1_30IRC-F16.json
```

改动：

- `lsc_v2.common.resolutionAll` 增加 `1920x1080`
- `resolutionAll_len` 从 `4` 改为 `5`
- 复制 `1280x720_*` 的 14 组 LSC 表为 `1920x1080_*`
- `tableAll_len` 从 `56` 改为 `70`

这仍是功能验证级 IQ 补齐，目的是让 AIQ 正常启动并能跑通链路；不是重新标定过的正式 1080p LSC。

## 5. 1080p60 编码修复

`v4l2_mpi_venc_probe` 能跑 `1920x1080@60`，但 `ipc_lite` 正式 `VI -> VENC bind` 路径最初一直 `frames=0`。

内核日志显示：

```text
frame info no equal set drop: frame [1920, 1080, 1920, 1080], prep [1920, 1080, 1920, 1088]
```

原因是 `ipc_lite` 把 VENC virtual height 设成 16 对齐后的 `1088`，但 RK_MPI VI 绑定送来的 frame info 是 `1080`。VENC 认为输入帧信息和 prep 不一致，连续 drop，所以编码端取不到流。

修复：

```text
attr.stVencAttr.u32VirHeight = config->video.height
```

buffer size 仍按配置保留足够空间，`1080p60` 配置中为 `3133440`。

## 6. 板端验证

板子：Luckfox Pico / RV1106

### 6.1 Raw V4L2

`1280x720@90`：

- `v4l2-ctl` 连续 120 帧通过
- 帧间隔约 `11.11ms`
- 统计约 `90fps`

`1920x1080@60`：

- `v4l2-ctl` 连续 120 帧通过
- 帧间隔约 `16.66ms`
- 统计约 `60fps`

### 6.2 v4l2_mpi_venc_probe

`720p90`：

- AIQ 启动成功
- UDP RTP sink 正常
- 120 帧短测无 stream drop

`1080p60`：

- AIQ 启动成功，没有缺 `1920x1080` IQ/LSC
- raw / ISP / VENC 路径可跑通
- probe 短测可出流，但在当前线程模型下 1080p60 已接近吞吐边界，不能只用 probe 的 stream drop 反推 sensor 不稳

### 6.3 ipc_lite 正式路径

`720p90`：

- `./run.sh ./ipc_lite.720p90.fast.udp.ini`
- 短跑约 `89.7-89.9fps`
- `timeouts=0`

`1080p60`：

- `./run.sh ./ipc_lite.1080p60.fast.udp.ini`
- 修复 VENC virtual height 后短跑正常出帧
- 统计约 `58-61fps`
- `timeouts=0`
- dmesg 中 VENC prep 变为：

```text
MPP_ENC_SET_PREP_CFG w:h [1920:1080] stride [1920:1080]
```

不再出现新的 `frame info no equal set drop`。

## 7. 常用命令

部署 MIS5001 driver：

```sh
MIS5001_BOARD_IP=192.168.3.54 project/scripts/mis5001-dev.sh build
MIS5001_BOARD_IP=192.168.3.54 project/scripts/mis5001-dev.sh deploy
MIS5001_BOARD_IP=192.168.3.54 project/scripts/mis5001-dev.sh reboot-reload
```

板端运行：

```sh
cd /root/ipc_lite
./run.sh ./ipc_lite.720p90.fast.udp.ini
./run.sh ./ipc_lite.1080p60.fast.udp.ini
```

短测前清理旧进程：

```sh
killall ipc_lite rkipc v4l2_mpi_venc_probe 2>/dev/null || true
```
