# AR9271 WPA2 连接失败排查与修复

## 现象

在当前镜像中切换到 `AR9271` 网卡后：

- 可以正常枚举为 `0cf3:9271`
- `ath9k_htc` 固件可正常加载
- 可以正常扫描到 `WPA2-PSK` AP
- 可以完成 `authenticated` 和 `associated`
- 但每次都会在关联后很快断开，无法拿到 IP

板端表现为：

- `wpa_state=SCANNING`
- `udhcpc` 一直拿不到租约
- 内核日志出现本地发起的 `deauth`

## 直接原因

通过 `wpa_supplicant -dd` 抓到的关键日志如下：

```text
wlan0: WPA: Installing PTK to the driver
nl80211: set_key failed; err=-2 No such file or directory)
wlan0: WPA: Failed to set PTK to the driver
wlan0: WPA: 4-Way Handshake failed - pre-shared key may be incorrect
```

这说明真正失败点不是 DHCP，也不是扫不到 AP，而是：

- `WPA2 4-way handshake` 的最后阶段
- `wpa_supplicant` 往驱动安装 `PTK` 时失败
- 因此 `wpa_supplicant` 本地主动发起 `deauth`

日志中的 `WRONG_KEY` 是 `wpa_supplicant` 的通用提示，不足以单独证明密码错误。

## 根因判断

结合驱动源码：

- `ath9k_htc` 的 `set_key()` 在 [sysdrv/source/kernel/drivers/net/wireless/ath/ath9k/htc_drv_main.c](/work/luckfox-pico/sysdrv/source/kernel/drivers/net/wireless/ath/ath9k/htc_drv_main.c#L1416)
- 该驱动支持模块参数 `nohwcrypt`，定义在 [sysdrv/source/kernel/drivers/net/wireless/ath/ath9k/htc_drv_init.c](/work/luckfox-pico/sysdrv/source/kernel/drivers/net/wireless/ath/ath9k/htc_drv_init.c#L30)

板端实测表明：

- 默认使用硬件加密时，`PTK` 下发失败
- 改为 `nohwcrypt=1` 后，WPA2 连接立即恢复正常

因此当前可确认的根因是：

- `AR9271 + ath9k_htc` 在当前板端环境下，硬件加密路径不可用
- 需要强制回退到软件加密

## 板端验证结果

运行时手工重载：

```sh
insmod /oem/usr/ko/ath9k_htc.ko nohwcrypt=1
```

随后板端实测结果：

- `wpa_state=COMPLETED`
- `CTRL-EVENT-CONNECTED`
- 成功获取 DHCP 地址
- 能 ping 通网关

本次实测获取到：

- `wlan0` 地址：`172.20.10.12/28`
- 默认网关：`172.20.10.1`

## 落地修复

修改文件：

- `sysdrv/drv_ko/wifi/insmod_wifi.sh`

把 `AR9271` 自动加载分支从：

```sh
insmod ath9k_htc.ko
```

改为：

```sh
insmod ath9k_htc.ko nohwcrypt=1
```

并加注释说明原因：

- `AR9271` 在当前环境下使用硬件加密会导致 `PTK` 安装失败
- 需要强制使用软件加密，才能稳定完成 `WPA2` 连接

## 结论

本问题的核心不是：

- 配置文件冲突
- DHCP 故障
- AP 不可见
- 单纯密码错误

而是：

- `AR9271` 当前硬件加密路径不可用
- 必须在模块加载时启用 `nohwcrypt=1`

后续若重新烧录镜像并走新的 `insmod_wifi.sh`，`AR9271` 的 `WPA2-PSK` STA 连接应默认按软件加密路径工作。
