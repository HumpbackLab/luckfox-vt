# MIS5001 1104x624@120 Readout Register Root Cause

Update 2026-04-22: this document is kept as a historical readout debug note.
The current implementation no longer exposes the `1104x624` sensor mode or
its `ipc_lite` ini files; the active modes are `1280x720@90` and
`1920x1080@60`.

Date: 2026-04-19

## Result

`1104x624` can run as a native high-speed sensor path at about `120.14fps`
on RV1106 CIF raw capture.

Validated on board `192.168.3.50`:

```sh
media-ctl -d /dev/media0 \
  --set-v4l2 '"m00_b_mis5001 4-0031":0[fmt:SGRBG10_1X10/1104x624@10000/1201500]'
media-ctl -d /dev/media0 \
  --set-v4l2 '"rockchip-mipi-csi2":0[fmt:SGRBG10_1X10/1104x624]'
v4l2-ctl -d /dev/video0 \
  --set-fmt-video=width=1104,height=624,pixelformat=BA10
v4l2-ctl -d /dev/video0 \
  --stream-mmap=3 --stream-count=1000 --stream-to=/dev/null --verbose
```

Observed:

- `frames=1000`
- `drops=0`
- CSI error count `0`
- final cadence: `8.32ms`, about `120.14fps`

## Root Cause

Lowering only the public HTS registers `0x310e/0x310f` is not sufficient.

When `0x3023=0x01` enables the high-speed segmented readout path, the sensor
uses a second timing/window register block:

- `0x3118/0x3119`: mirror VTS
- `0x311a/0x311b`: mirror HTS
- `0x311c/0x311d`: mirror Y start
- `0x311e/0x311f`: mirror Y end

Before this fix, `0x3118..0x3123` still contained full-resolution defaults,
for example:

```text
0x3118/0x3119 = 0x07d0
0x311a/0x311b = 0x0bb8
0x311c/0x311d = 0x0008
0x311e/0x311f = 0x079f
0x3120/0x3121 = 0x000c
0x3122/0x3123 = 0x0a2b
```

That mismatch caused the extra segmented RAW packet reported by CIF as
`csi size err`, commonly `size:0x460450`.

## Working Register Group

The stable group for `1104x624@120` is:

```text
0x3307 = 0x9c
0x3023 = 0x01
0x3011 = 0x2b

0x310e/0x310f = 0x0a60
0x310c/0x310d = 0x0294

0x311a/0x311b = 0x0a60
0x3118/0x3119 = 0x0294
0x311c/0x311d = 0x0294
0x311e/0x311f = 0x0505
```

Notes:

- `0x310e/0x310f = 0x0a58` remains a hard failure boundary, even with the
  mirror block synchronized and with `0x3307` increased.
- `0x0a60` is the reliable HTS floor found so far.
- Raising `0x3307` from `0x84` to `0x9c` raises the stable `0x0a60/0x0294`
  mode from about `101.66fps` to about `120.14fps`.
- `0x311c..0x311f` is the key fix for the extra segmented packet. Setting only
  `0x3023=1` without this mirror Y window produces frames but causes periodic
  `size:0x460450` errors and sequence drops.

## Negative Results

Scans that did not produce a clean fix:

- `0x4216/0x4217/0x4218/0x4240/0x4242`
- `0x4220..0x4223` data ID routing
- `0x4224..0x4233` output-size registers
- `0x3124/0x312b/0x312f`
- `0x3f38/0x3f42/0x3f44/0x3f49/0x3f4e..0x3f55`
- `0x3012/0x301c/0x3022/0x3024..0x3030`
